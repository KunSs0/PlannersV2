# 能力槽收敛方案（属性 / 阵营 / 仇恨 / 播放）

> 背景：Planners 曾用 5 个 install 槽接收宿主能力，全部由 FightCore 在 `FightCoreQueryBridge` 里注入。
> 结论：`attr.*` 改为直连 `AttributeDriver`；阵营改为 `EntityFriendlyPolicy` 统一策略；`anchored` 平移到 Planners 的 MythicMobs 威胁读取；`playback.*` 整体删除，音效迁到连招 modifier；`natural.*` 暂缓。

---

## 一、`attr.*`：删除 `installAttr`（已实施）

### 结论

删除 `ActionAttributeAccess.AttrReader` 与 `installAttr`；`attr.<id>` 由 Planners 直接读 `AttributeDriver`。

### 问题

FightCore 已经通过 `AttributeDriver.register(FightCorePlannersAttributeDriver)` 接入属性通道，`installAttr` 的实现只是二次转发同一份数据。结果是同一份数据两个入口：第三方属性插件只实现 `AttributeDriver` 时，`planners-proxy` 正常但 `attr.*` 返回 null，技能公式报 `requires a number, got: null`。

### 实施

| 位置 | 改动 |
| --- | --- |
| `module/action/ActionAttributeAccess.kt` | 删除 `AttrReader`、`installAttr`、`attr()`；只保留 `NaturalReader` |
| `module/action/ActionScopeFactory.kt` | `readAttr` 直接读 `AttributeDriver.get` 并求和；驱动未注册时返回缺失，不打断技能 |
| `fight-core` `FightCoreQueryBridge.kt` | 删除 `installAttr` 调用 |

`QueryScope.attrReader` 字段保留，作为作用域内部取值函数（`ActionScopeFactory` 注入实现），不再是对外能力槽。

---

## 二、`natural.*`：暂缓（未实施）

保留现状：读取器仍由宿主注入，FightCore 当前实现等于 `attr` 的汇总值。等属性侧收敛完成后再定"自然成长"的归属与实现。

---

## 三、`@enemy` / `@ally`：`EntityFriendlyPolicy`（已实施）

### 结论

阵营判定从 `module.action` 抬为与 `AttributeDriver` 同级的全局策略；未注册时提供默认实例，判定逻辑始终由 Planners 执行。

### 实施

`module/compat/faction/EntityFriendlyPolicy.kt`：

```kotlin
interface EntityFriendlyPolicy {
    fun checkEnable(): Boolean
    fun isFriendly(source: LivingEntity, target: LivingEntity): Boolean

    companion object {
        fun register(policy: EntityFriendlyPolicy)    // 主线程、唯一所有者、同一实例幂等
        fun unregister(policy: EntityFriendlyPolicy)  // 仅当前所有者；注销后回到默认
        fun current(): EntityFriendlyPolicy           // 永不为 null
        fun isFriendly(source: LivingEntity, target: LivingEntity): Boolean
    }
}
```

`module/compat/faction/DefaultEntityFriendlyPolicy.kt`：只把实体自身视为友方。`@enemy` 会先排除自身，因此默认等价于"全部敌对"；`@ally` 默认只保留自身。

| 位置 | 改动 |
| --- | --- |
| `module/action/BuiltinTargeters.kt:416,451` | 改调 `EntityFriendlyPolicy.isFriendly(...)` |
| `module/action/ActionFactionPolicy.kt` | 删除 |
| `fight-core` `compat/planners/FightCoreFriendlyPolicy.kt` | 新增实现，`isFriendly` 委托 `MythicFactionPolicy.shouldIgnoreFaction` |
| `fight-core` `FightCoreQueryBridge.kt` | 启用时 `EntityFriendlyPolicy.register(FightCoreFriendlyPolicy)`，停用时 `unregister` |

## 四、`target.anchored`：仇恨读取平移到 Planners（已实施）

### 结论

`anchored` 是技能侧概念，读取由 Planners 自己的 MythicMobs 兼容层完成；删除 `ActionCombatFacts.installAnchored` 与 FightCore 注入。

### 实施

`module/compat/mythic/MythicThreatAccess.kt`：按 `MythicMobsLoader.version` 分 mm4/mm5，取 `ActiveMob.threatTable.topThreatHolder`，与施法者 `uniqueId` 比对；非 MythicMobs 生物、未开启威胁表或威胁表为空时返回 false。

| 位置 | 改动 |
| --- | --- |
| `module/action/ActionScopeFactory.kt` | `anchoredReader` 注入 `MythicThreatAccess::anchored`；`forExecution` 派生作用域时一并传递 |
| `module/action/ActionCombatFacts.kt` | 删除 |
| `fight-core` `FightCoreQueryBridge.kt` | 删除 `installAnchored`、`isAnchored` |

语义变化：由原来的 Bukkit `Mob.target` 改为威胁表 `getTopThreatHolder()`，与"仇恨第一"一致；目标切换瞬间更准确。

`AnchoredFieldTest` 改为直接构造 `QueryScope(anchoredReader = ...)` 验证字段解析与条件/三元用法。

## 五、`playback.*`：整体删除，音效迁到 modifier（已实施）

### 决定

`playback.*` 不开放：一次播放内的临时变量没有合适的业务场景，且音效这类时序表现应由连招 modifier 负责，而不是由技能流程 + 播放标记去"补播"。

### 删除清单

| 位置 | 改动 |
| --- | --- |
| `module/action/query/QueryRoot.kt` | 删除 `PLAYBACK` 根 |
| `module/action/query/QueryPath.kt` | 删除 `queryPlayback` 与分派 |
| `module/action/query/QueryScope.kt` | 删除 `playbackReader` 字段与各派生作用域复制 |
| `module/action/ActionCombatFacts.kt` | 删除（随 `anchored` 一起） |
| `module/action/ActionScopeFactory.kt` / `AreaScopes.kt` / `TimerScopes.kt` | 删除 `playbackReader` 传递 |
| `src/test/.../PlaybackRootTest.kt` | 删除 |
| `fight-core` `FightCorePlaybackSetAction.kt` | 删除，并从 `FightCoreActionBridge` 注销 `fc.playback.set` |
| `fight-core` `FightCoreQueryBridge.kt` | 删除 `installPlayback`、`readPlaybackVariable` |

保留：FightCore 内部仍使用 `ServerPlayerPlaybackContext`（弹道分段状态、扫击去重等），属于 FightCore 自身实现，不再暴露给 Planners 查询。

### 配置迁移

`server-main/plugins/Planners/skill/knight_skill_8.yml`：

- 删除 `onPrayerStart`、`onPrayerMid` 两个只为播音效与打标记存在的流程；
- `onPrayerEnd` 去掉播放标记条件、`fc.playback.set` 与完成音效，只保留 `fc.emblem.rite` 与 `call`；
- `hook.fightcore.hammershield.def.callback` 只保留 `on-end: onPrayerEnd`。

`server-main/plugins/FightCorePlugin/config/behaviortrees/hammershield.yml`（`骑士技能8` 过渡）：

```yaml
- 1 PlaySound knight_emblem_rite_begin -volume 0.8 -pitch 1.0 -range 24
- 1 PlaySound knight_emblem_rite_chant -volume 0.8 -pitch 1.0 -range 24
- 17.4 PlaySound knight_emblem_rite_expand -volume 0.8 -pitch 1.0 -range 24
- 17.4 PlaySound knight_emblem_rite_holy_rain -volume 0.8 -pitch 1.0 -range 24
- 36 PlaySound knight_emblem_rite_complete -volume 0.8 -pitch 1.0 -range 24
- 36 Emit on-end
```

`on-start` / `on-mid` 的 Emit 随流程一起删除；播放时序与动画 tick 对齐，不再依赖回调去重。

## 六、附带修正：`ActionTrigger.matches`

FightCore 源码的 `FightCoreTriggers.PlayerBulletHit` 覆盖了 `ActionTrigger.matches(scope, arguments)`，但 Planners 源码与已发布的 3.8.0 都不含该方法（只有 fight-core 自带的 API jar 里有）。为了用本次构建的 API jar 编译 FightCore，补齐接口：

- `ActionTrigger` 新增默认 `matches(scope, arguments): Boolean = true`；
- `ActionRunner.fire` 在触发器主键匹配后调用它，按本次派发载荷筛选行。

这样 `on_player_bullet_hit{player-bullet=...}` 这类参数才真正生效（此前被忽略）。
