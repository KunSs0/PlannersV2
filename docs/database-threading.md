# 档案业务与数据库线程边界

在线档案以内存为业务权威。主线程完成校验、外部资源扣除、职业/技能/点数状态提交和完成通知；数据库消费已捕获的字段快照，独立异步保存。数据库失败只记录上下文，不退款、不恢复旧职业、不修改在线集合。

## 本次审计与调整

| 入口 | 原问题 | 当前行为 |
| --- | --- | --- |
| 选职、转职 | 主线程插入职业线和阶段，并读取生成主键 | 主线程立即生成稳定内存身份并发布职业；后台事务创建记录及当前阶段指针 |
| 技能创建 | 名为 Future 的接口实际同步 INSERT，再注册技能 | 先注册唯一运行时技能，返回内存完成结果；后台生成数据库主键 |
| 技能树学习 | 主线程持职业对象锁执行 JDBC 事务，SQL 失败退款 | 主线程校验并扣外部资源、技能点、发布节点；数据库独立事务保存结果 |
| 技能点、等级和经验保存 | 后台读取可变职业对象，和学习共用对象锁 | 变更后捕获固定字段快照；异步经验算法回主线程发布结果 |
| 技能等级、装备保存 | 多个异步任务并发读取同一可变技能，可能写入错序 | 捕获完整技能字段，统一队列依次保存 |
| 清空职业 | 独立异步删除与其他保存之间缺乏共同顺序 | 清空内存、属性和会话并发事件后，按旧身份异步删除 |
| 元数据保存 | 异步遍历在线对象并清空其普通变更集合 | 主线程释放变更并序列化字段；后台只保存固定值；退出补交最后变更 |
| 档案加载 | 独立异步查询并直接在后台注册和发布，可能读取尚未保存的旧状态 | 查询排在前序保存之后；回主线程验证登录代际，拒绝退出/重登后的迟到结果 |

数据库初始化、建表、用户 ID 创建和 LOCAL 既有结构迁移只随后台档案查询执行。两个后端的查询入口显式拒绝主线程调用。已扫描工程中的 Planners 数据库接口引用，未发现其他源码或业务脚本直接依赖已移除的写入接口。

## 队列与身份

`AsyncDatabaseQueue` 使用无阻塞提交和单消费者处理：提交方不等待数据库、连接池、Future、协程或对象监视器。读取和写入共用顺序。调度拒绝时完成异常结果并独立记录，不在调用线程执行 SQL，不自动重试。

事件可能重入：例如选职完成监听器发放技能点，清空完成监听器立即重新选职。`ProfilePersistence` 在当前调用线程暂存该次通知中的快照，完成通知返回后按“当前操作、监听器后继操作”的顺序提交后台队列。期间没有数据库锁或等待任务。

新职业线、阶段、技能和节点先获得低于 -1 的进程内唯一身份；-1 仍只表示无父阶段/无当前阶段。`RecordIdentity` 仅由后台消费者绑定和读取数据库自动生成的正主键，绝不修改在线对象的集合键或 RPC 身份。重新登录加载后使用数据库正主键。数据库表结构与自增主键保持原结构，无需迁移生产数据。

技能树学习的排他标记用于拒绝重复请求，不等待持有者，也不覆盖数据库阶段；条件准备完成后回主线程重检职业、配置、在线状态、互斥关系和节点等级。只有外部扣费自身失败才逆序恢复资源，持久化失败不进入该回滚边界。

原数据库写入 API、同步学习存储器、同步插入 Future 包装、空默认技能更新入口和已无调用的可空插入工具均已移除，没有保留旧实现或兼容转发。

## 验证

JDK 21 执行 `./gradlew.bat --no-daemon build`，114 项源码测试通过，0 失败、0 跳过。覆盖实际业务入口、SQL 闸门、并发提交、异常后继续处理、通知重入顺序、连续学习、数据库失败不回滚内存、调度拒绝、登录代际，以及 SQLite 上的真实事务和身份生命周期。

使用新构建 JAR 运行 server-main 既有 Nova 回归，服务端 4 项通过；客户端 3 项在本次合入远端后的验证中通过。运行中的服务端 JAR 尚未替换，未执行实服命令或生产数据库操作。SQLite 测试验证共用 JDBC 写入器，未连接实际 MySQL 服务。
