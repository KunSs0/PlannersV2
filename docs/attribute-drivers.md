# 属性驱动接入

Planners 统一管理驱动注册、主线程写入、在线档案补刷、配置重载代际和职业属性来源清理。外部插件只实现属性 API 转换，不维护玩家集合或调度任务。

## 注册与注销

在 Bukkit 主线程、双方插件可用后调用 `AttributeDriver.register(driver)`；同一实例重复注册幂等，其他实例覆盖会明确报错。注册会自动重算在线且档案已就绪的玩家。日志记录实际实现类。

卸载时调用 `AttributeDriver.unregister(driver)`。Planners 先使待执行任务失效，再通过原驱动移除在线玩家的 `planners-proxy`，最后调用 `onUnregister()`。非当前驱动注销不产生影响。Planners 自身停止也执行同一流程，不自动切换其他驱动。

驱动需要准备或释放专属外部资源时覆盖 `onRegister()`、`onUnregister()`；不需要独立资源时无需覆盖。通用线程与刷新规则不放进这些钩子。

## 数值与文本输出

职业、技能和技能树节点先汇总为物理属性 ID 与 `Double` Map，再进入 `AttributeDriver.setValues(...)`。具有原生数值 API 的插件覆盖实例方法 `setValues(...)`，直接使用 Map，不依赖属性显示名或文本关键字。

文本驱动使用接口提供的统一序列化：普通十进制、不截断小数、不输出科学计数法，负值使用单一负号。状态系统继续使用文本属性入口；文本和 Map 写操作统一经 Planners 主线程调度。异步 Map 输入在排队前复制，避免调用者修改。

驱动须按来源 ID 替换整组属性，空输出移除该来源，不能将职业刷新叠加为新来源。外部插件的装备、Buff 等来源保持独立。通用输出不对属性取整；最终资源容量的取整由资源系统负责。

未注册驱动时，输出或读取会报告明确异常，避免属性静默丢失。未知属性 ID 由目标驱动的公开 API 明确校验。

## 刷新时机

- 档案加载、转职完成、技能等级和技能树节点变化。
- `PlayerLevelChangedEvent`：直接设置等级完成或经验算法异步完成后，通知实际提交的等级。原 `PlayerLevelChangeEvent` 保留其现有修改前语义，属性刷新不订阅它。
- 成功重载后的 `PluginReloadEvents.Post`：重算在线且档案就绪的玩家。

任务执行时重新读取当前属性，检查玩家在线、档案实例与代际。重载开始失效旧任务，并停止接收写操作；重载成功后恢复。重载失败不会写入半套配置。

## 验证

JDK 21 执行 `gradlew.bat --no-daemon build`。`AttributeTokenTest` 覆盖小数和数值协议；`AttributePipelineTest` 覆盖注册所有权、数值钩子、异步输入隔离、已有档案补刷、离线/换档案、重载和卸载失效，以及等级提交完成通知。
